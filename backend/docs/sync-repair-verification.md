# 仓库同步修复验收（2026-10-08）

修复基于 `246e365` 合并后的仓库。分类保留 31 个细类、十个后台大类和五个展示组，规则版本升级为 `poi-categories-v2.2`。

## 实现

- 名称与标签使用共享分类器。具体词只遮蔽相同位置的泛化词；无声明关系的独立冲突进入审核，不参与正式统计。忽略教育父标签，保留独立培训负向证据和已声明次类。
- 预算配置允许合法类别子集，采集配置与建计划入口必须覆盖全部所选类别；不隐式补充预算。路线会话兼容无预算对象。
- 三类回放与完整目录测试分开构造证据。完整目录回归覆盖十类轮转、单轮 60 次限制、分轮补全、边界只计算一次、累计路线限额和旧报告不可变。
- 契约导出共享模型清单，OpenAPI 包含续查接口、完成状态和分类目录。当前合成 mocks 与前端契约重新生成。
- WAL 在建库时初始化，空闲连接保留 WAL 生命周期。每次请求前后仍等待检查点持久化，序列化与写盘移到工作线程；取消时先等在途写入结束，防止写入顺序颠倒。
- 修复关闭时 POI 消耗取消异常后，后台队列继续等待新任务导致的退出挂起。

## 性能对比的范围

同一环境串行交替运行 40 次，比较合并基线 `246e365` 的检查点函数与当前函数，使用半径 1300 米、全目录调度状态并执行 JSON 序列化；先确认两者输出一致。基线平均 7.918 ms，当前平均 5.269 ms，降低约 33%。当前保留可变字段的隔离复制。

这是序列化微基准，不能外推为整个报告生成速度。WAL 空闲连接的单独写入对比没有显示明确提速，不据此宣称性能收益。没有减少持久化频率。完整多轮目录用例在最终全量测试中耗时 126.51 秒，仍是主要性能负担。
