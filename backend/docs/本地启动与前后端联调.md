# 本地启动与前后端联调

核对日期：2026-09-20；代码基线 `chore/hybrid-only-validation`（`ebd61aa`）。本轮运行环境为 Windows、Python 3.11.7、Node 24.20.0、Microsoft Edge。算法包声明 Python >=3.11；前端使用 package-lock 锁定依赖，建议沿用本轮验证的 Node 24。当前正式 Web 的 `/api/analyses` 已接入团队百度边界搜索（E8.2，`local-multicross-e82`），`/api/v1/analysis/hybrid` 继续运行 Hybrid；严格 POI/端点证据已通过生产 poiEvidence 契约接入；E8.3 实验构圈/调度仍不属于生产 HTTP。

生产 HTTP、领域语义、字段映射与兼容策略见 [前端接口契约](../../life-circle-demo/docs/前端接口契约.md)。此文给出从仓库安装、启动和重复验收的方法；不包含真实密钥。

## 1. 安装（Windows PowerShell）

从仓库根目录开始。后端既要安装锁定依赖，也要安装本地算法包；只安装 FastAPI 不够。

```powershell
Set-Location 'D:/AI比赛project/Baidu-map'
py -3.11 -m venv backend/.venv
$analysisPython = (Resolve-Path backend/.venv/Scripts/python.exe).Path
& $analysisPython -m pip install -r backend/requirements.lock.txt -e ./life-circle-algorithm
Set-Location life-circle-demo
npm.cmd ci
```

已有环境时跳过创建，不覆盖自己的环境。仓库原 README 使用 uv 也可：从 backend 执行 `uv pip install --python <Python路径> -r requirements.lock.txt -e ../life-circle-algorithm`。本轮复用的 Python 在 `D:/CodexCaches/baidu-map-algorithm-venv/Scripts/python.exe`，它不是团队必须使用的路径。

## 2. 优先 synthetic 联调

终端 A，在仓库根目录：

```powershell
$analysisPython = (Resolve-Path backend/.venv/Scripts/python.exe).Path
$env:ANALYSIS_PROVIDER = 'synthetic'
Set-Location backend
& $analysisPython -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1 --no-access-log
```

检查 [health](http://127.0.0.1:8000/health) 和 [Swagger](http://127.0.0.1:8000/docs)。synthetic 不发送百度 walking 请求，不需要服务端 AK；`baidu_ak_configured` 仅是配置布尔值，不代表权限测试。常规 app 会加载 backend/.env，本轮自动验收另用隔离入口，不读取该文件。

终端 B，在仓库根目录：

```powershell
Set-Location life-circle-demo
$env:VITE_ANALYSIS_MODE = 'api'
$env:VITE_API_BASE_URL = 'http://127.0.0.1:8000'
npm.cmd run dev
```

打开 [前端](http://127.0.0.1:5173)。环境变量也可写入本机 `life-circle-demo/.env.local`，修改后重启 Vite。不要提交这个文件；不要自动覆盖已有配置。

- `VITE_ANALYSIS_MODE=api` 为 API 入口；仅 `demo` 进入旧演示，未配置也为 API。
- `VITE_API_BASE_URL` 是服务根地址，不带 `/api/analyses`。未设置则同源；当前 Vite 没有自动代理，分端口联调必须配置。
- `VITE_BAIDU_MAP_AK` 是浏览器类型密钥，用于底图、选点、搜索和定位。没有它时地图降级为提示，仍可输入坐标完成分析和查看摘要/报告。地图真实显示需用户在本机配置并验收。
- 浏览器地图坐标和 API center 均为 BD09LL，数组按 `[lng,lat]`，不要把浏览器定位的原始坐标直接当百度坐标。

按顺序验收：启动后端 → health → 启动前端 → 输入/点击选点 → 开始分析 → 创建/轮询/整理结果 → 自动报告 → 关闭再打开 → 修改条件显示 stale → 失败/证据不足不覆盖旧报告 → 取消/重试。synthetic 的 facilitiesStatus 是 not_integrated；设施数量显示未知，不能记为 0 或假设施结果。

## 3. 真实步行模式（由操作者单独核验）

在 backend/.env 本机配置服务端 `BAIDU_MAP_AK` 与账户允许的正数 `ANALYSIS_QPS`，不要把密钥写到命令行、测试报告或任何 VITE_* 中。`ANALYSIS_PROVIDER` 的配置值为 **baidu**，响应的 dataSource 才是 **baidu_walking**，两者不能混写。

停止终端 A 后将 `$env:ANALYSIS_PROVIDER = 'baidu'`，仍用上节 uvicorn 命令重启。已有环境变量优先于 .env，切换前确认只检查变量名/非敏感配置，不打印整个环境。浏览器 AK 与服务端 AK 分开；真实服务需要操作者确认对应权限、白名单、配额和 QPS。健康检查不能证明 walking 可用。

真实模式使用共享 QPS gate，不能为跑快擅自调高；未设 AK/QPS 时创建返回 503。E8.2 不要求先用预算完成旧网格初始化，QPS 只影响推进速度，不会因预算与截止时间不匹配而拒绝创建。真实模式没有自动 synthetic 回退。先受控小规模核验，不批量重复点击；单个生产分析预算为 200/400/800，设施阶段和路线点击另有调用，不应把预算当成整次 HTTP 请求总数上限。

本轮没有进行真实 Provider smoke，没有验证真实底图、UID 路线、权限或配额。自动测试用离线地图 SDK 替身和合成算法；不能写成真实百度端到端验收。

## 4. 端口、CORS 与错误排查

| 现象 | 核对项 |
| --- | --- |
| 创建 POST 404 | VITE_API_BASE_URL、是否启动当前 backend、Swagger 是否含 POST /api/analyses；不要误报为任务过期 |
| 已有 taskId GET 404 | 内存任务不存在/30 分钟过期/进程重启/访问了另一服务；取消多 worker 和热重载实验 |
| 409 | 已有活动任务、幂等 key 内容不同、结果未就绪；按状态恢复或取消，不无条件再 POST |
| 422 | center{lng,lat} 数值、coordinateSystem=bd09ll、budget=200/400/800、clientRequestId 合法 |
| 503 | 服务端 AK/QPS 未配置或预算与截止不匹配；不通过前端伪造数据绕过 |
| 路线 429 | 当前任务最多 3 次新增设施路线查询；优先使用已有缓存 |
| network/CORS | 后端进程、端口、浏览器来源与 CORS_ORIGINS；不要只看 health 即判定跨域成功 |

默认前端 5173、后端 8000；CORS 默认允许 `http://127.0.0.1:5173` 和 `http://localhost:5173`。换端口需配置明确来源的 JSON 数组，例如 `CORS_ORIGINS=["http://127.0.0.1:5178"]`；来源不带路径/末尾斜杠，不用 `*`。任务只存在单进程，最多一项运行、终态最多 20 条。实验不用多个 worker、不用 reload。停止服务分别在两个终端 Ctrl+C；停止后任务清空。

## 5. OSM 是独立路径

当前浏览器不调用 `POST /api/v1/analysis/osm_offline`。synthetic 联调不需要下载 OSM 数据。OSM 配置由 `OSM_PBF_PATH`、`OSM_GRAPH_CACHE_PATH`、`OSM_DATA_VERSION`、`OSM_METRIC_CRS`（默认 EPSG:32651）、`WALK_SPEED_MPS`、`SNAP_MAX_DISTANCE_M`、`ISOCHRONE_BUFFER_M`、`OSM_COVERAGE_BOUNDARY_PATH`、`OSM_COVERAGE_MARGIN_M` 控制。数据和缓存缺失不应误判为百度任务接口缺失。独立验收按照 [OSM 数据说明](../../data/osm/README.md) 和 [OSM 报告](OSM_OFFLINE.md)，不要把其响应强转成任务 Result。

## 6. 自动验收：隔离凭据，可重复运行

在仓库根目录准备**被忽略**的空环境目录，Vite 测试借此不加载真实 .env.local。ANALYSIS_TEST_ENV_DIR 仅用于离线测试，正常开发不设置。backend 测试入口只在 tests 下隔离设置；backend/app 的 schema/adapter/result assembly 有最小修改；算法、Provider 和 scheduler 未改。

```powershell
New-Item -ItemType Directory -Force .tmp/final-integration/empty-env | Out-Null
$env:ANALYSIS_TEST_ENV_DIR = (Resolve-Path .tmp/final-integration/empty-env).Path
$env:ANALYSIS_TEST_PYTHON = (Resolve-Path backend/.venv/Scripts/python.exe).Path
$env:INTEGRATION_OUTPUT_DIR = "$PWD/.tmp/final-integration/web"
$env:DEMO_OUTPUT_DIR = "$PWD/.tmp/final-integration/demo"
$env:PYTHONPYCACHEPREFIX = "$PWD/.tmp/final-integration/pycache"
Set-Location life-circle-demo
npm.cmd test
npm.cmd run build
npm.cmd run test:analysis-ui
npm.cmd run test:integration
npm.cmd run test:e2e
Set-Location ..
& $env:ANALYSIS_TEST_PYTHON backend/tests/run_web_acceptance.py
git diff --check
```

按顺序运行，减少本机浏览器抢占导致超时。现有 Playwright 配置使用已安装的 Edge (`channel: msedge`)。API UI 使用 5179 的 Vite + HTTP 替身；integration 使用 8018 的真实 FastAPI + 5178 的真实 Vite，算法是实际 synthetic，地图 SDK 离线替身；原 Demo E2E 用 5173。端口被占时先由操作者停止对应开发服务；测试设置 reuseExistingServer=false，避免误连旧进程。测试结束 Playwright 自动关闭它启动的服务。

后端 runner 只屏蔽仓库凭据文件，使用本地模拟 Provider；输出在 .tmp/final-integration。上一轮两个 xfail 已移除：最终嵌套 PoiEvidence schema 和枚举必须真实 PASS。新增生产 HTTP 测试通过 httpx.MockTransport 覆盖可达、超时阈值、偏移、缓存不增发请求和 Result/路线证据一致性；不是访问真实百度。生产代码不得导入 tools；实验语义函数仅在测试中作为对照。

测试结束，在当前 PowerShell 清除 `ANALYSIS_TEST_ENV_DIR`（`Remove-Item Env:ANALYSIS_TEST_ENV_DIR`），避免以后正常启动 Vite 时仍屏蔽本机地图配置。其他测试路径变量也可在关闭测试终端时清除。

### 使用新证据

- 查看 Result 的 data.facilities[].poiEvidence：status 为 pending、verified_reachable、verified_unreachable；请求/实际端点、偏移与 observedDuration 均在同一个对象。
- poiEvidence.version 固定 1.0，字段映射与 null 规则见 [契约第 10 节](../../life-circle-demo/docs/前端接口契约.md)。不是上一轮建议的平铺 poiStatus；新的正式对象在设施和路线中复用同一 schema。
- reason 非 null 时 duration=null；endpointVerified 只说明端点解析成功；observedDuration 是诊断，不能直接当作请求 POI 的有效 duration。
- 两端按 E8.3 的 <=1e-5 米容差严格匹配，900 秒包含边界。原 Provider 的 50 米偏移容差不作为严格确认依据。返回路线 >900 秒显示“返回路线超过15分钟”，不声称不存在其他更快路线。
- 未查询/失败/偏移保持 pending，unknown 不计为不可达。未采样路线不会为凑齐状态而新增调用。
- 旧响应缺少 poiEvidence 或为 null 时明确显示“旧版结果未提供严格证据”，前端不补造 pending。对象存在但缺必需字段、错误版本或证据自相矛盾时拒绝消费。
- 路线查询可补充同一任务快照；后端 Result 和路线缓存同步，前端设施/报告统计同步。不会改变几何、计数阈值或原报告中心，不跨任务采用迟到响应。

后端 HTTP 坐标 schema/TypeScript 现在使用 serialization 输出别名，新增了类型生成漂移测试；不再依赖旧 validation alias。旧 backend/docs/N05 静态快照仍是历史材料，最新响应以运行中 Swagger 和 app.contracts 为准。

P0：证据表达与严格状态生产 adapter 已实现，两个发布测试真实通过，无剩余 P0。P1：真实 Provider/底图、UID 路线与端点实际偏移仍需用户受控 smoke。P2：原 Demo 隐藏图表的 ECharts 尺寸警告、现有 Starlette/AnyIO 弃用提示不在本轮扩大修复。

本轮发布结论（仅限严格 POI 证据生产接入）：生产接口冻结 YES；前后端集成完成 YES；建议由用户 review 后 commit/push YES。两个 xfail 已删除，P0=0，所有上述测试与 build 通过；本工具未执行 commit/push。这不表示 E8.3 实验构圈算法已成为生产算法，也不表示真实百度 smoke 已完成。

## 9. 2026-09-20 双入口与 E8.2 接入验收

启动方式不变（第 1～3 节命令可直接沿用）。与上一轮的区别：

- 真实模式创建任务只要求 AK 与 QPS 已配置；旧网格的“初始化预算必须在截止时间内完成”不再作为 E8.2 的准入条件。
