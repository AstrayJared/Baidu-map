## 3. 正式前端使用的任务接口

本地基地址默认 `http://127.0.0.1:8000`。业务坐标为 `[经度, 纬度]`，必须显式 `bd09ll`；不要传 WGS84/GCJ02 或演示画布坐标。

| 方法与路径 | 请求/响应 | HTTP 状态 |
| --- | --- | --- |
| `POST /api/analyses` | 提交中心、坐标系、预算、客户端请求标识，返回任务视图 | 202；输入错 422；忙或标识冲突 409；真实配置不足 503 |
| `GET /api/analyses/{taskId}` | 查询任务视图 | 200；不存在/过期 404 |
| `GET /api/analyses/{taskId}/result` | 读取完成结果 | 200；未完成/失败/取消 409；不存在 404 |
| `POST /api/analyses/{taskId}/cancel` | 无请求体，幂等取消，返回任务视图 | 202；不存在 404 |
| `POST /api/analyses/by-request/{clientRequestId}/cancel` | 丢失创建响应时按原标识取消，不创建新任务 | 202；不存在 404 |
| `GET /health` | `status`、`baidu_ak_configured` 布尔值 | 200；不证明步行权限和白名单通过 |

创建请求示例：

```json
{
  "center": {"lng": 121.513926, "lat": 31.313077},
  "coordinateSystem": "bd09ll",
  "budget": 200,
  "clientRequestId": "guodingyi-example-001"
}
```

预算只支持 **200/400/800**，默认 400。未知字段、字符串坐标、布尔预算不接受。中心归一化为六位小数。同一标识和相同归一化中心、预算复用任务；同标识用于不同参数返回 409。幂等性仅在任务仍保留时有效，30 分钟过期或服务重启后不再保证复用。

任务视图字段：`taskId`、`status`、`stage`、`requests`、`networkRequests`、`budget`、`elapsedSeconds`、`dataSource`、`error`。状态为 `running / cancelling / completed / cancelled / failed`；运行阶段包括 `initializing / expanding / exploring / refining / reconstructing`。进度表示真实阶段和计数，不是估算百分比。

| 完成结果字段 | 含义 |
| --- | --- |
| `taskId / dataSource / center / generatedAt` | 任务、`baidu_walking` 或 `synthetic` 来源、BD09LL 中心、Unix 秒时间戳 |
| `facilitiesStatus` | 当前固定 `not_integrated` |
| `isochrone.coordinateSystem` | 固定 `bd09ll` |
| `isochrone.geometry` | 可达 Polygon/MultiPolygon；有效空集合与 `null` 不同，null 表示证据不足 |
| `unknownRegion / uncertainRegion / computationExtent` | 位于 isochrone 内，分别为未知、不确定及计算范围几何 |
| `quality` | `usable / partial / insufficient`，也是 isochrone 字段 |
| `stopReason / warnings` | 真实停止原因与边界提示，例如 budget、deadline、range_truncated、unfinished_boundary，不应被前端改写 |
| `statistics / config` | 调用、重试、未知面积（平方米）、未完成边界等统计及实际算法配置 |

任务 `completed` 表示算法执行结束，不代表几何必然完整：partial 和 insufficient 仍可作为完成结果返回。`geometry_error` 或执行异常才单独失败。取消后的任务不提供完成结果，迟到响应不能覆盖终态。

`networkRequests` 是 Scheduler 的尝试预留计数；在 Provider 限流等待期间取消，可能已预留但尚未真正发送。真实费用审计以发送前持久化账本及交接记录为准，不能只凭前端计数认定百度计费。

当前每进程最多一个任务运行，忙时不排队。终态保留 30 分钟、最多 20 条，重启不恢复。CORS 默认允许 `http://127.0.0.1:5173` 与 `http://localhost:5173` 的 GET/POST，不提供身份认证。

## 4. 并存的 N05 契约接口

| 路径 | 用途及差异 |
| --- | --- |
| `GET /api/v1/analysis/mock/{scenario}` | scenario 为 complete/partial/failed/empty，固定 Mock，无真实步行 |
| `POST /api/v1/analysis/synthetic` | 同步返回合成计算结果；origin、coordinate_system、scenario、budget；场景 plane/local_failure/global_failure，预算整数 144～800 |

这套接口使用 `schema_version=1.0`、`analysis_id`、`coordinate_system` 和 `data`，来源为 mock/synthetic/system；状态是 complete/partial/failed/empty。它与任务接口的 camelCase 字段、completed 状态及 baidu_walking 来源不同，当前不提供真实异步任务生命周期。示例和完整模型见 [N05 契约](N05-接口契约.md)，在线 OpenAPI 位于 `/docs`。正式前端的等时圈流程使用第 3 节接口。

## 7. 下一步建议

以下为基线交付时的原计划；短时稳定性、固定独立点集和首轮 400 预算比较现已执行。下一步优先审查并锁定实验工具的记录保护修复，补充边界附近独立参考点，再安排跨时段重复或扩大预算，不能由本次一个点的差异认定自适应稳定优于均匀网格。

1. 合并 PR 后锁定实验提交与依赖版本；在同一服务端出口、单进程条件下先做一轮有明确预算的连续稳定性验证，对照百度控制台时间图，确认新限流策略的耗时和故障率。
2. 固定国定一社区的独立验证点集：道路可通行区、边界内外、围墙/入口、跨路通道与未知区域均覆盖；验证点不得参与算法采样，所有测时使用同一 Provider 和坐标口径，采集时间单独记录。真实调用预算包含验证点、失败和重试，先形成清单再运行。
3. 先比较自适应、均匀网格和扇形三算法各 400 次预算。仅训练/采样部分最多 1200 次尝试，独立参考集另计；不能把 1200 当作整个实验总预算。统一范围、阈值、参考集及时间窗口，报告误纳、漏纳、边界误差、拓扑、未知比例、成本与失败原因。
4. 数据质量及参考覆盖足够后，再扩展 200/400/800 和关闭主动补测、关闭探索的消融。点集只能支持点分类误差时，不冒称面积 IoU；正式社区 IoU/P95 需要足够独立的面与边界参考证据。
5. 算法稳定后再接真实设施检索、去重、圈内判定与设施统计，另立验收范围。N05 与任务 API 的统一作为后续兼容性工作，不在本次 PR 中改动前端契约。
