## 1. 目标、范围与技术基线

### 1.1 目标

采用以下主线，在有限步行路线 API 调用预算内，重建中心点周围的近似 15 分钟步行可达区域：

```text
中心点
  → 粗网格角点与中心点采样
  → 步行 API 测时
  → 四叉树细分与边界主动补测
  → 重建带未知区域标记的时间场
  → 提取 900 秒等值线和可达多边形
  → 输出几何结果、质量说明与调用统计
```

第一版优先验证两个问题：

- 同样的调用预算下，自适应算法是否比扇形、均匀网格更准确？
- 达到相近精度时，自适应算法能否减少调用？

不预先宣称自适应算法一定更优，以实验结果判断。

### 1.2 与现有项目的关系

依据现有[总体技术方案](./15分钟生活圈_技术实现方案.md)，沿用 React 前端、Python/FastAPI 后端方向。当前仓库只有模拟前端，尚无真实地图接入和算法后端。

本算法先实现为可独立测试的 Python 模块，再接入分析任务服务。

| 内容 | 本方案处理方式 |
| --- | --- |
| 步行测时 | 使用服务端单起终点步行路线接口 |
| 等时圈 | 自行采样、插值和提取 |
| 批量距离矩阵、官方等时圈 | 不作为前置依赖 |
| 底层路网与生产最短路引擎 | 不自行建设 |
| 设施统计 | 提供复用测时能力；设施自身耗时独立核验 |
| 1 公里服务盲区 | 保持独立，不纳入本算法 |
| 前端代码、数据库、部署 | 本轮不修改 |

Python 计算部分拟使用 NumPy、Shapely，并新增 ContourPy 负责规则栅格等值线提取；调度、缓存和优先队列尽量使用标准库。具体版本在实现阶段验证后锁定，不将拟用依赖描述为已安装依赖。后续安装、缓存和较大实验数据默认放在 D 盘。

### 1.3 结果含义

设起点为 $S$，路线接口返回的预计步行耗时为 $T(S,P)$：

$$
\Omega=\{P\mid T(S,P)\le900\}
$$

算法输出的是有限采样对 $\Omega$ 的近似，不是实地步行时间保证。

必须区分：

| 结果 | 含义 |
| --- | --- |
| 实测点可达 | 有效路线耗时不超过 900 秒 |
| 实测点超时 | 有效路线耗时超过 900 秒 |
| 估计可达区域 | 根据实测点插值得到 |
| 边界不确定区域 | 已有数据，但分辨率或插值可靠性不足 |
| 未知区域 | 缺少足够有效测时，不能分类 |

不得用请求失败代表超时，也不得把启发式评分称为统计置信概率。

## 2. 算法实现方案

### 2.1 坐标和时间口径

首版输入与地图输出统一使用 **BD09LL**，内部坐标顺序统一为 `[经度, 纬度]`。供应方适配器负责转换成接口要求的参数顺序。

局部采样使用以中心点为原点的近似平面坐标：

$$
x=R\cos(\varphi_0)(\lambda-\lambda_0),\qquad
y=R(\varphi-\varphi_0)
$$

其中角度转为弧度，$R=6371008.8$。

这只是基于 BD09LL 的局部采样尺度，不是 BD09 到 WGS84 的转换。下文网格尺寸和几何距离均指该局部近似米制尺度；正式步行判断始终使用 API 返回秒数。

其他规则：

- 输入必须显式声明坐标系；首版拒绝未支持的坐标系，不隐式猜测。
- 发往百度的经纬度统一保留 6 位小数，缓存使用实际请求坐标。
- 数值 `900` 判为可达，`900.1` 判为超时。
- 时间容差只影响补测优先级，不改变业务阈值。
- 输出采用带 `coordinateSystem: "bd09ll"` 的业务几何对象，不标称为标准 WGS84 GeoJSON。[RFC 7946 坐标规定](https://www.rfc-editor.org/info/rfc7946/#section-4)

### 2.2 初始参数

以下是首轮实验默认值，属于本方案提出的参数，不是既有配额、实测性能或赛题要求。

| 参数 | 默认值 | 用途 |
| --- | ---: | --- |
| 时间阈值 | 900 秒 | 业务判定 |
| 初始范围 | 中心周围 ±1600 米 | 3.2 公里见方 |
| 最大范围 | 中心周围 ±3200 米 | 最多扩大一次 |
| 初始格边长 | 400 米 | 全域粗采样 |
| 细分层级 | 400 → 200 → 100 → 50 米 | 四叉树细化 |
| 边界关注带 | 900 ±120 秒 | 补测优先级 |
| 主动补测时间残差目标 | 30 秒 | 检查预测边界 |
| 主动补测空间间隔下限 | 25 米 | 控制重复补测 |
| 输出栅格间隔 | 25 米 | 插值与等值线提取 |
| 默认请求预算 | 400 次 | 包含失败与重试 |
| 对比实验预算 | 200、400、800 次 | 比较成本与精度 |
| 非边界探索预留 | 总预算的 10% | 检查容易漏采的区域 |
| 单点最大尝试次数 | 2 次 | 首次请求加一次重试 |
| 单次请求超时 | 8 秒 | 防止挂起 |
| 实验任务截止时间 | 600 秒 | 到时输出已有结果 |
| 并发上限 | 2 | 初始工程配置 |
| QPS | 接入时按实际权限配置 | 不从截图推断 |

若 QPS 或任务截止时间不足以完成初始化，启动前返回配置不足提示。

400 次请求在 1 QPS 下，仅限速就至少需要约 400 秒；在 5 QPS 下约 80 秒。因此首版不设置未经测量的秒级出图承诺。

### 2.3 初始化与共享采样

初始范围分为 $8\times8$ 个格子：

- 角点：$9\times9=81$ 个。
- 格中心：$8\times8=64$ 个。
- 合计 145 个位置；起点自身作为 $T(S,S)=0$ 的数学锚点，无需请求。
- 无缓存、无重试时，需要 **144 次 API 请求**。

初始格子的中心点必须测量。四角都超时，不能据此删除格子；内部可能存在可达通道。

建立全局采样注册表：

- 同一请求位置只保留一个测时记录。
- 相邻格共享角点、边中点与边界主动采样点。
- 已经在途的相同请求共享同一个结果。
- 请求最终失败后保留未知状态，不能因多个格子引用而无限重试。

一次四分裂通常新增四个边中点和四个子格中心，最多增加 8 个采样位置；实际调用先经过共享点去重。

### 2.4 细分优先级

每个格子维护四角、中心及边上新增实测点。

定义：

- $C$：有效样本同时存在 `≤900` 与 `>900` 时为 1，否则为 0。
- $N=\max(0,1-\min|T_i-900|/120)$：接近边界的程度。
- $R_c=|T_{\text{center}}-\operatorname{mean}(T_{\text{corners}})|$：中心实测与四角预测的偏差。
- $V=\max T_i-\min T_i$：格内时间跨度。
- $L$：格边长。

首版使用确定性的启发式评分：

$$
U(c)=\frac{L}{400}
\left[
4C+2N+
2\min\left(\frac{R_c}{120},1\right)+
\min\left(\frac{V}{300},1\right)
\right]
$$

中心或角点无效时，不计算相应数值项，转入未知数据处理。

满足以下任一条件的格子进入候选队列：

- 可达与超时样本混合；
- 存在距阈值不超过 120 秒的样本；
- 中心预测偏差超过 60 秒；
- 格内有效时间跨度超过 300 秒。

队列优先处理评分最高的格子，评分相同按固定空间编号排序。

剩余 10% 探索预算用于细分未被选中的同侧粗格，优先选择较大、尚未探索的格子，使用固定种子决定同级顺序。预算不足一个完整细分组时，将余额归还主队列。

这能降低漏采风险，但不能保证发现所有窄通道或孤立区域。

### 2.5 下一次采哪里

默认决策顺序：

1. 候选格边长大于 100 米时，优先四分裂。
2. 格边长不超过 100 米，且存在跨越阈值的相邻边上样本时，优先预测边界位置。
3. 预测补测未消除明显偏差，且格子仍大于 50 米时，再四分裂。
4. 达到最小格尺寸后，保留未解决的不确定性。

对一段已有实测边 $AB$：

$$
\alpha=\frac{900-T_A}{T_B-T_A},\qquad
P=A+\operatorname{clip}(\alpha,0.1,0.9)(B-A)
$$

执行规则：

- 仅对有效、分处阈值两侧的端点使用该公式。
- 候选点距已有样本不足 25 米时，不继续增加近重复点。
- 单个叶格边最多增加两个主动补测点；共享边统一计数。
- 每次补测后重新检查全部相邻实测区间，允许一条边存在多次状态变化。
- 不把整个方向上的距离—耗时关系假定为单调。
- 主动补测点必须进入后续时间场重建，不能只用于统计。

### 2.6 时间场重建与等值线提取

**采样网格与输出栅格分开。** 四叉树负责决定在哪里调用 API；规则栅格负责统一提取几何结果。

重建流程：

1. 将每个叶格边上的全部共享采样点按空间顺序排列，包括相邻细格造成的中间节点。
2. 用叶格中心连接相邻边界点，形成三角片。
3. 在三个顶点均有有效耗时的三角片内，采用重心坐标线性插值。
4. 相邻叶格使用同一份共享边样本，保证边上的插值一致。
5. 将局部时间场统一采样到 25 米规则栅格。
6. 缺少有效支持的三角片及其影响的栅格单元标为未知，不跨越未知区域插值。
7. 用 ContourPy 提取 900 秒边界和阈值以下的填充区域。

ContourPy 参数固定为：

```python
name="serial"
corner_mask=False
quad_as_tri=True
fill_type="OuterOffset"
z_interp="Linear"
```

采用单个计算分块；填充范围为 `filled(-1, 900)`，其中有效耗时均非负。`OuterOffset` 保留外环与孔洞关系，未知点采用保守遮罩。[ContourPy 参数说明](https://contourpy.readthedocs.io/en/stable/api/contourpy/contour_generator.html)、[填充结果格式](https://contourpy.readthedocs.io/en/stable/user_guide/calculate/fill_type.html)

几何处理规则：

- 保留多个分量和孔洞。
- 不使用凸包包围全部可达点。
- 首版不做平滑、填洞或按面积删除小分量。
- 最终可达几何必须裁剪到有效插值支持区域，防止栅格跨过较小的未知缺口。
- 对角交替状态由固定等值线算法消歧，并通过专项用例验证；数值连通不能直接解释为真实道路连通。
- Shapely 校验失败时报告几何错误，不静默修补成可能扩大可达范围的形状。

25 米输出栅格只是绘图分辨率，不代表每 25 米都调用了 API，也不代表边界误差已经达到 25 米。

### 2.7 范围扩展、停止和质量标记

当外围格样本仍出现 `≤1020 秒`，或估计可达区域接触计算范围边缘时，尝试将范围扩大到 ±3200 米。

扩大后沿用原有采样，只补外圈。保持 400 米初始格时，完整新增外圈需要最多 400 个采样位置。预算不足时保留当前结果并标记可能截断。

边缘请求失败只意味着范围判断未知，不单凭失败继续扩张。

停止条件包括：

- 所有候选已达到空间细化限制及补测规则；
- 请求预算耗尽；
- 任务截止或取消；
- 达到最大范围；
- 上游权限、配额或连续故障使任务无法继续。

输出质量：

| 状态 | 判定 |
| --- | --- |
| `usable` | 在当前搜索范围及分辨率下完成既定检查，无已知数据缺口或范围截断 |
| `partial` | 有可用几何，但仍有未细化边界、未知数据或范围截断 |
| `insufficient` | 有效支持不足，不能构成可用区域 |

`usable` 仍表示有限采样下的近似结果，不表示证明了全域正确。

## 3. 模块接口与接入规则

### 3.1 算法模块接口

以下为拟新增的内部接口签名示意，不代表仓库已经存在对应实现：

```python
async def query_walking_time(origin, destination, deadline) -> RouteObservation: ...

async def compute_isochrone(request, provider, cancel_token) -> IsochroneResult: ...
```

| 对象 | 必须包含的内容 |
| --- | --- |
| `IsochroneRequest` | 中心点、坐标系、900 秒阈值、采样配置、预算、截止时间、配置版本 |
| `RouteObservation` | 实际请求坐标、有效耗时或未知原因、采集时间、尝试次数、可获得的路线端点信息 |
| `IsochroneResult` | 估计可达几何、不确定区域、未知区域、计算范围、质量状态、停止原因、调用统计 |

几何允许多多边形和孔洞。有效计算得到空区域时返回空几何；因证据不足无法生成时返回 `null`，两者不能混同。

### 3.2 百度接口适配

采用已核查的服务端步行路线接口：

```text
GET https://api.map.baidu.com/directionlite/v1/walking
```

适配器显式设置 `coord_type=bd09ll`、`ret_coordtype=bd09ll`，并按接口要求使用“纬度,经度”传入起终点。返回 `duration` 的单位为秒。[百度步行路线规划文档](https://lbs.baidu.com/docs/webapi?title=directionlite/guide/webservice-lwrouteplanapi/walk)

规范化规则：

- 多条有效方案取最小耗时。
- 耗时缺失、负数、非有限值或结构异常时，返回未知。
- “无返回结果”按未知处理，不解释为已确认不可达。
- 网络超时、临时服务错误允许一次受控重试。
- 权限错误、无效参数不重试；账户配额耗尽停止调度。
- 开启分段信息，用可获得的路线端点检查绑路偏移；不能把回显请求坐标当成实际道路端点。
- 能确认请求点与路线端点偏移超过 50 米时，该测时不直接作为原采样点的有效证据。
- 端点信息不足时记录未核验标记，并纳入不确定性说明。

接入第一步验证服务端 AK 的实际权限、限速和响应结构。引用对话中的小程序配置不能证明服务端权限已开通。

### 3.3 调度、预算和缓存

- 每次真正发送请求前，原子占用一个预算名额。
- 失败、重试均消耗预算；缓存命中不消耗新请求预算。
- QPS 限速与并发控制同时生效。
- 截止或取消后不再发新请求；迟到响应不能更新已经结束的任务。
- 连续五个采样位置在重试后仍发生临时上游故障时，停止新增采样并返回已有结果。
- 首版采用任务内缓存，跨任务在线缓存默认关闭。

缓存键包含供应方、接口版本、起终点实际请求坐标、坐标系、影响路线的选项及适用的 POI 标识。起终点有方向，不能交换后复用。

记录：

```text
实际请求数、唯一采样位置数、缓存命中数、重试数、
失败分类、请求延迟、总耗时、计算耗时、
各层格子数、未知面积、未完成边界和停止原因
```

日志及测试夹具不保存带凭据的完整请求 URL。

### 3.4 前端与设施模块

现有 Demo 的 `circle: Point[]` 只能表达示意单环。后续真实接入应使用带坐标系、孔洞、多分量和质量说明的等时圈对象，不把真实结果压回示意坐标。

前端保留现有分析服务的职责划分：创建分析、查询状态、获取结果。进度展示已完成采样数、预算使用和阶段，不把“使用了多少预算”冒充算法完成百分比。

设施统计独立查询中心点到设施的耗时：

- `≤900 秒`计为可达；
- `>900 秒`不计入；
- 未知单独统计；
- 不仅通过点是否位于估计多边形内决定设施可达性。

| UT-06 | 四角可达、中心超时 | 识别内部异常，不能填满整个格子 |
| UT-07 | 非单调边上耗时 | 保留多次状态变化，不进行全方向单调二分 |
| UT-08 | 新主动点与原插值显著不符 | 新点参与重建，并改变对应时间场或边界 |
| UT-09 | 相邻格尺寸不同 | 共享边插值一致，无拼接裂缝、重叠面或重复边 |
| UT-10 | 对角交替状态、恰等于 900、等值平台 | 消歧确定，无除零、自交或非确定结果 |
| UT-11 | 凹形、孔洞、多分量 | 保留结构，不被凸包或清理步骤覆盖 |
| UT-12 | 未知点、未知缺口、整片失败 | 不跨未知区填充；证据不足时返回 `insufficient` |
| UT-13 | 并发请求与重试接近预算上限 | 实际请求总数始终不超过预算 |
| UT-14 | 超时、取消、迟到响应 | 停止新增调用，结束后的结果不再被改写 |
| UT-15 | 边缘可达、扩展预算不足 | 返回部分结果与截断说明，不冒充完整 900 秒边界 |
| UT-16 | 已确认的大幅绑路偏移 | 原位置不被直接判为有效实测 |
| UT-17 | 响应完成顺序变化 | 固定夹具与配置下输出等价，调用数量一致 |
| IT-01 | 多路线、权限错误、限流、异常响应 | 适配器正确分类，执行规定重试与停止策略 |
| IT-02 | 设施位于估计圈内但路线超时 | 不计为 15 分钟可达设施 |
| UI-01 | 中心点切换后旧任务返回 | 地图、统计、报告不被旧任务覆盖 |

### 4.3 合成场景

| 场景 | 真值或构造方式 | 主要检查 |
| --- | --- | --- |
| 匀速平面 | $T=\sqrt{x^2+y^2}/1.2$，真值半径 1080 米 | 基本形状与边界误差 |
| 方向不对称 | 固定各向异性解析时间场 | 不强行生成圆或对称结果 |
| 河流与单桥 | 测试路网仅允许经桥跨越 | 绕行导致的凹陷与误纳 |
| 围墙与单入口 | 固定障碍和入口路网 | 近距离点仍可能超时 |
| 内部孔洞、多分量 | 专用标量场夹具 | 几何拓扑，不解释为真实社区结论 |
| 狭窄通道 | 20、50、100 米及不同网格偏移 | 分辨率限制与漏采敏感性 |
| 时间突变 | 跨边界耗时突变 | 不把跳变当作可靠连续边界 |
| 局部或全局故障 | 固定区域返回未知 | 遮罩、质量状态和降级结果 |

窄于采样尺度的通道可能完全没有命中。此类用例用于暴露限制，不设置“有限采样必须发现所有通道”的不可实现验收条件。

### 4.4 对照算法与公平实验

设置三组：

1. **扇形基线**：32 个方向，每个方向先取四个距离层，再对最外可达区间局部补测；记录星形表达的限制。
2. **均匀网格基线**：选择预算能覆盖的最大规则点阵，使用相同阈值和等值线提取配置。
3. **自适应方案**：四叉树、中心采样、非边界探索和边界主动补测。

实验规则：

- 合成场景分别运行 200、400、800 次预算上限。
- 所有方法使用相同起点、范围、测时来源和终止规则。
- 记录实际调用数；预算相同但未用满时，不能声称实际调用数相同。
- 验证点和参考真值不能被采样器读取。
- 共享测时回放只能返回算法实际请求的位置；不得把其他算法的样本提前注入。
- 回放实验同时记录“逻辑查询成本”和“真实新增网络请求数”。
- 增加两项消融实验：关闭主动补测、关闭非边界探索，分别检查它们的实际贡献。

### 4.5 指标与初始验收目标

| 指标 | 计算口径 |
| --- | --- |
| 区域 IoU | 预测与真值交集面积 ÷ 并集面积 |
| 误纳率 | 错误判为可达的数量或面积 ÷ 全部预测可达 |
| 漏纳率 | 未判为可达的真实可达数量或面积 ÷ 全部真实可达 |
| 边界距离 P95 | 双向边界距离的第 95 百分位 |
| 未知比例 | 未知区域面积 ÷ 计算范围面积 |
| 成本 | 实际请求数、唯一位置数、重试数 |
| 性能 | 总耗时、网络等待、算法计算耗时、请求延迟 |

未知结果不能从误差评估中直接删除：真实可达但未给出可达预测的点计入漏纳，并单独报告未知比例。范围截断或参考边界不完整时，不报告完整边界误差。

初始工程门槛：

- 上表单元与契约测试全部通过。
- 请求预算超限、把未知当超时、跨未知区域填充属于阻断问题。
- 匀速平面场景在 800 次预算下，以 **IoU ≥0.95、边界距离 P95 ≤75 米**作为初始回归目标。
- 复杂场景逐项报告结果，不用总体均值掩盖河流、入口等场景的失败。
- 自适应方案只有在独立验证集上显示精度或成本优势后，才能宣称优于基线。

以上数值是拟定的工程试验目标，不是已经取得的结果，也不替代[需求分析文档](./15分钟生活圈_需求分析.md)中尚需确认的正式业务准确度标准。

### 4.6 真实场景验证与报告模板

真实验证首先选择一个已确认的社区中心，运行三种算法的 400 次预算实验；随后扩展到桥梁绕行、封闭街区等场景。当前 Demo 的虚构位置不能作为真实测试样例。

每个中心建立独立验证集：

- 100 个覆盖整个测试范围的分层抽样点；
- 100 个针对出入口、桥梁及边界附近的挑战点；
- 两组分别报告，不能直接混合成整体准确率；
- 与算法样本偶然重合的点，按预先固定的规则从同层预留点替补；
- 调参与最终评估使用不同验证集。

独立 API 测时检验的是对供应方时间函数的重建能力。现场步行核验另列来源、日期和条件，不与 API 自洽性验证混称为真实步行准确率。

测试报告至少包含：

```text
案例名称与中心点：
坐标系与采集时间：
算法、配置版本与预算：
实际请求数、重试数和耗时：
验证数据来源与样本规模：
精度指标及未知比例：
孔洞、分量与范围截断情况：
失败样例及对应截图：
与基线的差异：
结论与适用限制：
```
