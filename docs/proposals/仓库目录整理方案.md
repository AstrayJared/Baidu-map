## 0. 结论

项目经历过两次目录整理：一次集中搬迁**在同一批改动里被撤回**，一次"先建索引、分批迁移"的方案**从未合入**。结果是仓库继承了两次整理的*产出*（根目录启动器、一个只装一份文档的 `docs/`），却没有继承任何一次的*规则*；两个独立仓库又被放在主仓库工作区内且未被忽略。

因此本方案不重做一次"大搬迁"，而是：

1. **先划边界、再建索引、最后分批迁移**（沿用未合入方案 `4c839bb6` 的策略，而不是被撤回的 `68c336c3`）。
2. **运行路径一律不动**：`backend/`、`life-circle-demo/`、`life-circle-algorithm/`、`data/`、三个启动器、契约生成目标在本次整理中保持原位。搬迁的每个路径都有代码级代价（见 §6）。
3. **两个独立仓库迁到与主项目同级**，各自保留 Git 历史、远端、CI 与 Pages 工作流；不采用 submodule/gitlink。
