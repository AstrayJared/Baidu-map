# 评审启动指南

## 交付物与环境

- 源码仓库，根目录 MIT LICENSE、第三方许可说明及自动测试工作流。
- 离线附件 `shanghai-20260912-runtime.zip` 和 `shanghai-20260912-runtime.zip.sha256`，两者放在同一目录；不将运行数据加入 Git。
- Python 3.11+（验收使用 3.12）、Node.js `^20.19.0` 或 `>=22.12.0`。
- 评审自行配置百度服务端 AK 和浏览器端 AK；需要地点检索、步行路线、Geoconv 坐标转换及浏览器地图相应权限。配置与账号配额仍以评审自己的账号为准。

## 一次准备并运行

从源码根目录执行：

```powershell
python dev.py setup --sample-package "附件所在目录/shanghai-20260912-runtime.zip"
python dev.py doctor
python dev.py
```

启动器按提示准备依赖与密钥。导入前校验压缩包和全部文件，安装到项目数据目录，只修改 OSM 配置并备份原 `.env`。该路径不需要准备阶段的 Pyrosm/编译器。依赖首次安装仍需软件源网络；“离线附件”指路网数据可离线安装，真实地图、POI 和路径规划仍需百度服务网络。

打开本地页面，选择“国定一社区样例”，点击“开始体检”。首次城市路网加载通常需数分钟；本次上海样例从提交到报告约 14 分钟（同时运行回归测试，不能视为性能承诺），界面按真实阶段显示进度。切换算法和刷新不会取消任务，显式取消才停止。

导入与检验也可单独执行：

```powershell
python backend/scripts/setup_osm_region.py import "附件所在目录/shanghai-20260912-runtime.zip"
python backend/scripts/setup_osm_region.py verify "data/osm/regions/实际安装目录"
python backend/scripts/setup_osm_region.py clear
```

`clear` 只清除 OSM 配置，不删除数据、密钥或历史体检。手工构图仍可使用现有 `prepare_osm_graph.py` 及导出风险/障碍工具；本轮未提供在线下载器或多城市自动构建命令。

## 页面验收

1. **位置与坐标**：百度地图选点、搜索和定位均使用 BD09LL。选择 GCJ02/WGS84 时填写源坐标、点击“应用坐标”，官方转换成功才更新中心。失败显示原因，不使用本地近似公式兜底。
2. **成圈与设施**：900 秒真实步行端点证据生成近似等时圈；分类、去重和圈内统计保留检索限制。圈外邻近设施可为圈内提供服务，但不计入圈内数量。
3. **基础三项专项**：菜市场、独立药店、小学分别评估 1000 米步行服务；超市、诊所、幼儿园不能替代三项。切换专项类别可筛选疑似缺口与专项热力。
4. **三态结论**：检索充分但没有该类候选时标“未检索到／疑似缺口”；入口不明、检索不完整或路网支持不足保持未知。100 米容差带表示不确定，不能将标准扩张为 1100 米。
5. **报告与评分**：总体分仅为购物、医疗、教育三大类等权区间；三项专项独立呈现，不改变总体分。任务 completed 不等于精度已全部验收。旧报告无专项时明确显示未评估。

## 自动验证

后端在 `backend` 目录执行：

```powershell
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider --basetemp=logs/submission-tests -o faulthandler_timeout=0
.\.venv\Scripts\python.exe -m tools.export_contract --check
```

慢用例到 120 秒会记录用例名与各线程的 Python 栈；任务终态断言仍按原时限执行。

前端在 `life-circle-demo` 执行 `npm test`、`npm run build`、`npm run test:checkup-ui`、`npm run test:integration`。算法包在其目录执行 `../backend/.venv/Scripts/python.exe -m pytest -q`。浏览器使用 Playwright Chromium；本机可设 `PLAYWRIGHT_CHANNEL=msedge`。离线测试不读真实 AK，不访问百度；真实验收独立执行并记录实际预算。

## 版本、配额和限制

运行包固定 `geofabrik-shanghai-20260912`，米制坐标 EPSG:32651、步速 1.3 m/s，来源与原始 PBF/各文件校验值见 manifest。风险、水体障碍与路网必须使用一致版本；没有适用的水系复核时采用 OSM 原样并说明限制，不冒充已实地确认。

每轮地点检索默认/上限 1200 次，核验累计上限 120；失败重试计预算、缓存不计新增网络，应用日额度与共享限流仍生效。坐标转换使用独立的应用限制，默认 1 QPS、100 次/日，不等于百度账号权益。

坐标转换的参数依据[百度官方 Geoconv v2 文档](https://lbsyun.baidu.com/docs/webapi?title=geoconv%2Fguide%2Fchangeposition-base)：GCJ02 使用 model=1，WGS84/GPS 使用 model=2。真实验收已验证两种来源；BD09LL 原样返回、不占上游额度。HTTP 200 中的配额、限流和权限业务错误也分别提示，定义见[官方状态码说明](https://lbsyun.baidu.com/faq/api?title=lbscloud%2Fapi%2Fappendix)。

已知限制包括目录完整性、入口和通行权限、路网快照时效、成圈近似及抽检范围；报告保留未知与证据等级。实时围挡、门禁、矩阵并发、多城市自动化、人口容量、选址规划及重启续查属于后期方向。


## 提交状态与 CI

用户自行配置 AK，本机账号额度不作为提交阻塞项。项目负责人确认复现、固定疑似缺口样例与独立核验通过；原始实测数据和未执行调用不改写。远端 CI 执行步骤及本机测试汇总见根目录 README，精确提交 SHA 和运行链接见工作流 `submission-ci-receipt` 附件；七个任务全部成功才记录远端通过。
