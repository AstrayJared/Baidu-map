# 15 分钟生活圈前端

基于需求分析与技术方案实现的可交互前端演示。使用 React、TypeScript、Vite、Ant Design、CSS Modules、ECharts；状态由 Context + useReducer 管理。

生产入口同时保留「百度边界搜索（E8.2）」和「OSM＋百度」（Hybrid v1.5）页面，通过顶部算法选择器切换。E8.2 走 `/api/analyses` 并保留设施与路线能力；Hybrid 走 `/api/v1/analysis/hybrid`，圈面扣除 OSM 水体。界面不标注两者的速度或精度优劣；两套结果和任务互不混用，便于开发期间对比。

先按 [后端 README](../backend/README.md) 启动离线服务，再启动前端。当前实际请求、字段、错误与状态规则见 [前端接口契约](docs/前端接口契约.md)，历史验收见 [接入任务报告](../backend/docs/算法前后端接入任务报告.md)。下方“演示操作”及设施场景表仅适用于 `VITE_ANALYSIS_MODE=demo` 的原演示入口。

最新统一安装、启动、错误排查与离线验收步骤见 [本地启动与前后端联调](../backend/docs/本地启动与前后端联调.md)。严格 POI 证据已通过生产 poiEvidence 契约接入，映射与兼容策略见接口契约第 10 节。两个生产入口目前只提供真实计算的 15 分钟圈，不生成 5/10 分钟圈。Hybrid 地图只画 15 分钟圈外轮廓线（后端 `displayGeometry`），不填色、不画水体内孔；该字段缺失时退回原几何外环。E8.3 实验构圈入口仍不对浏览器开放。

## 配置与模式

- `VITE_ANALYSIS_MODE=api` 或 `baidu`：初始选择百度边界搜索（E8.2）；`hybrid`：初始选择 OSM＋百度；`demo`：显式启用原设施模拟演示。非 demo 模式都可在页面顶部切换两种生产算法。
- `VITE_API_BASE_URL`：未配置时使用同源 `/api/analyses`；本地前后端分端口运行时，请显式设为 `http://127.0.0.1:8000`。部署地址由环境配置提供。
- `VITE_BAIDU_MAP_AK`：浏览器地图 AK，与后端步行 AK 分开配置。API 模式中地图缺配置或加载失败会显示错误，坐标输入与结果摘要仍可使用。
- 浏览器 AK 需在百度控制台开通 JavaScript API GL、「地点检索」与「地理编码」服务，来源白名单需包含实际访问地址（如 `http://127.0.0.1:5173`）。
- 「获取当前位置」需浏览器授权，仅 HTTPS 或 localhost/127.0.0.1 可用；定位精度不足时界面会提示在地图上核对。地点搜索优先列出分析中心周边 5 公里结果，并附少量较远选项（分组展示；较远选项要求标题严格包含关键词）。附近与全城均无结果时，通过地址解析兜底全国范围的行政区/地址名称（结果标注「地址定位」，如搜索县名）。定位与搜索均返回 BD09LL 坐标，只在用户点击「开始分析」后随中心坐标发送至后端；搜索关键词直接发往百度检索服务。地图不可用时两项控件降级为说明文字。
- 可复制 `.env.example` 为本地 `.env.local` 并重启 Vite；不要在任何 `VITE_*` 中填写服务端 AK。
- API 入口支持 200/400/800 次预算，每秒轮询；等待时复用原 Loading 的雷达视觉，展示创建任务、真实计算阶段、整理结果与取消，不模拟完成百分比。开始按钮和控制器防止重复创建。后台忙时稍后重试；创建接口 404 提示地址/配置问题，已有任务 404 才提示任务过期。

## 分析结果与报告

默认 API 入口沿用 `/api/analyses` 创建、轮询、结果及取消接口。响应先经过运行时校验和显式适配，再核对任务、数据来源、中心点和预算，进入已有地理 `AnalysisResult`。不会将 BD09LL 结果强转为 Demo 平面坐标；多分量、孔洞、空几何和 null 均保留。

获得可用或部分等时圈后自动打开分析报告；关闭后可通过“查看分析报告”重新打开。修改坐标或预算后，旧结果与报告保留并显示原条件提示；失败、服务不可用或证据不足不会覆盖上一份可用结果。地图图层、摘要与报告共用成功快照，待分析选点与已分析中心分别标注。报告不受图层开关影响。API 入口使用真实任务进度；原 Demo 的 Loading、Report MVP 与 DemoMap fallback 保持原流程。

`synthetic` Provider 固定返回 `facilitiesStatus: "not_integrated"`，三类设施数量和盲区数量均为“无法确定”；真实 `baidu_walking` Provider 会在等时圈计算后执行有限设施检索与采样点核验，返回 `facilityAnalysis`（设施列表、`in_circle` 三态、查询证据、采样点三态与步行路线接口）。设施计数是“检索记录 · 估算圈内”，不代表全量目录；`serviceBlindRegions` 当前为空几何，不展示面积盲区结论；不能把算法未知区域当成设施盲区，也不会从 Demo 补数据。报告来源明确区分 `synthetic` 和 `baidu_walking`。`/api/v1/analysis/mock/*` 和 `/synthetic` 是另一套契约验收接口，不作为任务 API 的备用数据源。

## 本地运行

已验证环境：Node.js 22.22.1、npm 10.9.4。依赖具体版本记录在 `package-lock.json`。

在文件夹中打开 cmd 或 PowerShell：

```powershell
npm ci --cache D:/CodexCaches/npm
npm run dev
```

打开 [本地 Demo](http://127.0.0.1:5173/)。已经安装依赖时只需 `npm run dev`。端口占用时不会自动切换，避免误打开其他项目；可先检查占用程序或指定其他端口启动。

已有 `node_modules` 时直接使用，构建输出仍为 `dist`；下载缓存默认使用上述 D 盘路径。浏览器测试截图、报告与临时文件位于 D 盘，使用本机 Microsoft Edge。首次安装依赖如需将 `node_modules` 也放在 D 盘，见接入任务报告中的目录联接命令。

```powershell
npm test
npm run build
npm run test:analysis-ui # 前端 HTTP 契约/地图替身回归，无需 Python 或真实 AK
npm run test:integration  # 真实 FastAPI + 合成 Provider + 模拟 SDK，禁止外部网络
npm run test:e2e          # 原演示入口回归
```

集成测试启动专用端口 5178/8018，不复用已有服务；默认 Python 为 `D:/CodexCaches/baidu-map-algorithm-venv/Scripts/python.exe`，可用 `ANALYSIS_TEST_PYTHON` 覆盖。产物默认在 `D:/CodexOutputs/isochrone-integration`；`INTEGRATION_OUTPUT_DIR`、`DEMO_OUTPUT_DIR` 可分别覆盖两套测试产物目录。

## 演示操作

1. 选择青禾街区 A、B、C 任一预设点，或在地图上点选 / 输入任意坐标。
2. 选择演示场景，然后点击「开始体检」。
3. 使用地图上方的类别筛选、左侧图层开关查看设施和区域；地图支持拖动、缩放及复位。
4. 点击设施点位或右侧问题卡片，在地图查看详情。
5. 点击「查看完整体检报告」，查看本次分析的全类别结果。

手机或窄屏下分析面板移到地图下方堆叠，右侧概览通过「查看结果」抽屉查看。坐标输入后需要先点击「应用坐标」。示意地图范围内任意中心点均可分析，A、B、C 为快捷预设；超出示意地图范围会提示重新选点，不会套用其他位置的结论。

### 固定场景

设施使用固定地理坐标，A、B、C 三个中心点位置不同，15 分钟圈内看到的设施组合与数量也不同：

| 演示点 | 正常结果（圈内设施） |
| --- | --- |
| A 点 | 7 处：菜市场 4、药店 2、小学 1 |
| B 点 | 6 处：菜市场 2、药店 2、小学 2 |
| C 点 | 6 处：菜市场 2、药店 3、小学 1 |

| 场景 | 内容 |
| --- | --- |
| 正常结果 | 按上表统计并显示 15 分钟圈内设施；圈外设施不在图中展示 |
| 设施缺失 | 东北住区两处菜市场从数据中移除，展示一个菜市场服务盲区 |
| 数据不足 | 药店数据不完整，数量显示「—」，问题区域显示「无法判断」，不计为盲区 |
| 分析失败 | 同一预设点首次失败，重试成功；刷新页面后重置模拟失败记录 |

设施地理坐标固定，不同演示点看到的设施集合与圈内数量不同；地图和列表仅显示 15 分钟圈内设施，圈外设施不展示、不计入数量。概览和报告始终为全类别结果，地图及列表响应类别筛选。

15 分钟范围与 1 公里盲区独立展示；距离口径和评估范围仍为演示条件，不在前端推导正式业务结论。单点结果不代表全社区覆盖率或服务质量。

## 工程结构

```text
src/
  main.tsx           默认 API / 显式 Demo 入口选择
  analysis/          API client、校验适配、任务控制、地图、报告、定位与搜索
  App.tsx            工作台、分析表单、结果列表和报告
  Map.tsx            可替换的 SVG 地图渲染与交互
  Chart.tsx          ECharts 分类统计图表
  Store.tsx          状态容器与异步分析编排
  state.ts           状态转换及过期请求隔离
  service.ts         四类异步能力及可复现模拟任务
  data.ts            三个演示点与固定场景（设施走分类管线）
  domain.ts          坐标示意映射、分类筛选和统计
  types.ts           业务类型与类别定义
  taxonomy.ts        设施大类/小类、关键字字典与边界配置
  classify.ts        名称归一化与关键字匹配、误类排除
  dedup.ts           稳定 UID 去重与兜底键
  geofence.ts        圈内判定
  pipeline.ts        分类→去重→圈内判定，地图与统计的唯一结果源
  fixtures/          验收样例（每类≥5条、误类、重复 UID）
  domain.test.ts     业务数据与状态测试
  classify.test.ts   分类与误类排除测试
  dedup.test.ts      UID 去重测试
  pipeline.test.ts   管线与地图/统计一致性测试
tests/
  demo.spec.ts       Playwright 浏览器流程验收
docs/
  前端接口契约.md     正式任务接口、配置、字段、状态、能力边界及本地联调
  设施分类与UID去重说明.md   分类字典、去重、圈内判定与验收说明
```

API 页面通过 `analysis/service.ts` 获取后端结果并经适配进入地理结果模型；原 `service.ts` 继续服务 Demo。`Map.tsx` 已有百度地图与 SVG fallback。SVG 示意坐标映射不是地理坐标转换算法，两种结果模型不能混用。

## 检查与构建

```powershell
npm test
npm run build
npm run test:e2e
```

- Vitest：统计、未知状态、预设点匹配、任意点分析、盲区远近、过期结果隔离、服务重试，以及设施分类、误类排除、UID 去重与地图/统计一致性。
- Playwright：完整流程、图层与筛选、报告、三处预设点、自定义坐标、任意点分析、异常及窄屏操作。
- `npm run build`：TypeScript 检查与生产构建。
- 浏览器测试产物：analysis-ui 在 `output/analysis-ui`，集成与 Demo 默认在上文所述 D 盘目录，可用相应环境变量覆盖。

端到端测试自动启动独立服务，不复用已有服务。执行前应确保配置指定的端口空闲。浏览器测试使用系统 Edge；其他环境需安装 Edge 或调整 Playwright 的浏览器配置。

生产构建可通过 `npm run preview` 本地查看。运行服务时仅监听 `127.0.0.1`，没有发布到互联网。
